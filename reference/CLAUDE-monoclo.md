# Проєкт: Telegram-бот Монокло (замовлення → таблиця, звірка, оплати, звіти)

Повне технічне завдання — у файлі `TZ.md`. Читай його повністю перед роботою; це єдине джерело вимог.
Якщо щось у ТЗ суперечить цьому файлу — питай власника, не вгадуй.

## Хто замовник
Власник бренду, **не програміст**. Усе, що він має зробити руками, — пояснюй українською, покроково,
без жаргону. Жодних терміналів, clasp, Google Cloud Console, сервісних акаунтів чи хостингу для нього.

## Стек і обмеження (обов'язково)
- Тільки **Google Apps Script**, прив'язаний до нової Google-таблиці «Монокло — Виробництво 2026». Без серверів.
- Telegram — через `UrlFetchApp`, отримання оновлень **через `getUpdates` з тригера щохвилини**. Вебхук (`doPost`) не використовувати (302-редирект Apps Script → дублі).
- Токени (Telegram, API Нової пошти) — лише в `PropertiesService.getScriptProperties()`, вводяться діалогом з меню.
- Часовий пояс `Europe/Kyiv`. Мова всіх текстів бота і меню — українська.
- Колонки шукати **за назвами заголовків**, не за літерами.
- Усі записи в таблицю — під `LockService`; пакетні `setValues`, не по клітинці.
- Стара таблиця «Звітність Монокло — Кузнець 2026» — **тільки читання** (імпорт). Ніколи не писати в неї.
- Гроші: бот ніколи сам не ставить «Оплачено» без натискання кнопки власником. Ідемпотентність скрізь (повтор оновлення/файлу/тапу не створює дублів).

## Що віддати в кінці
1. Папка `apps-script/` з файлами з розділу 10.1 ТЗ **і** додатково `apps-script/ALL_IN_ONE.gs` — увесь код одним файлом
   (щоб власник вставив один файл замість дев'яти) + `apps-script/appsscript.json`.
2. `ІНСТРУКЦІЯ-ВСТАНОВЛЕННЯ.md` — кроки з розділу 10.2 ТЗ, під фінальний код, з назвами пунктів меню точно як у коді.
3. Тести логіки, яку можна перевірити без Google: розбір підпису замовлення, нормалізація ТТН/розмірів/типу/кольору,
   категорії звірки і розрахунок різниць, правила імпорту. Винеси цю логіку в чисті функції без викликів Google API
   і перевір їх через Node (`node --test` або простий скрипт) на файлах з `test-data/`.
4. Короткий `ЗВІТ.md`: що зроблено, що перевірено, що лишилось перевірити вже в Google (і як).

## Як працювати
- Спершу коротко перекажи власнику план (модулі й порядок), потім роби по черзі: таблиця і меню → модуль 1 →
  статуси НП → модуль 2–3 (звірка/оплата) → звіти → імпорт.
- Після кожного модуля запускай тести і коротко пиши, що готово.
- Не додавай функцій, яких немає в ТЗ. Якщо бачиш покращення — запропонуй, але не роби без згоди.
